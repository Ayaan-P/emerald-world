# Historical characters without a lifetime population ceiling

Independent app-only draft based on #393 b10c53543c682115ecab29a66c343f3ec441a00f. Native pin remains #57; not RC12-based. Frozen #384/#56 and Maya integration remain unchanged. No pending native changes are included.

An author still explicitly retires a generated character through the existing validated action pipeline. Retirement is not death. On a later successful mechanic admission, already-committed retired records move atomically from bounded live state into immutable historical_characters rows in the existing world SQLite database. New/active/away records cannot be dropped this way. Original history, individual companion rows, action receipts and identity remain intact. There is no new model call or player-save change.

Thirty-two remains the live-record limit. Relationships to historical NPCs retain small authority-derived references; complete archived records retain their own relationships, goals, team identities, evidence and authored reason. An incoming script's fabricated archive references are replaced with authoritative references. Exact old retired records can replay harmlessly; changed or resurrected archived records and rendered objects under archived IDs are rejected at admission. Publication failure rolls back archive rows and the live-state change together. Archive lookup only fetches identities relevant to the current candidate rather than loading the whole lifetime cast.

Agents discover world.recall_character alongside existing capabilities. Empty identity and an after cursor page eight historical identities; an exact ID returns its dated final authored record and archive sequence. This is not first-hand knowledge or proof of a battle. Existing world.search_history/world.read_history retrieve original evidence. A local host can use the existing authenticated admin socket with {"command":"character_archive","identity":"id"} or {"command":"character_archive","after":""}. This is not a new unauthenticated network endpoint. The existing player-facing world journal displays archive events and retains the earlier full character changes. No new native character archive screen is claimed.

Known scope: only generated world_characters, not canonical cast records. Pending retired records compact on the next successful mechanic admission, not at a wall-clock deadline. Other per-module budgets/state remain unchanged; this is not a promise of unlimited active objects or an unlimited total runtime budget. Back up the whole world database as before, not only the mechanic state JSON.

Tests exercise actual authority admission, 32 retired records plus a newcomer, retained relationship references, exact replay, resurrection rejection, failed-admission rollback, paged recall and restart. No live provider, rendered game or linked native test was performed.
