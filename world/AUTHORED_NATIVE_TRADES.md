# Experimental authored native trade templates

Independent native draft based on #80, 999b40dc0bb9471a9d54e6f34154c64fb7c09dea. Not Maya #72 or released RC12. No held bridge/activity/worker files changed.

WORLD_TRADE_OFFERS defaults to 0. When explicitly enabled, `/npc-trade ACTOR` asks the authenticated authority for a nearby stationary generated resident's published template. This initial command is not a trade. The native script explains that the offered Pokemon is newly generated, repeatable, at the selected Pokemon's level, with no held item, and is not the NPC's personal companion. Players choose Yes, use the stock party/PC chooser, and separately confirm giving the selected Pokemon and its held item away. No provider chooses a party member or confirms.

The reviewed catalog is 20 ordinary species. Templates use native initial moves, native stats from fixed 15 IVs, default ability slot, a locally generated personality/OT ID, native species nickname and WORLD OT. Actual stock trade evolution applies after exchange. No level, IV, item, move or ribbon parameters are accepted from agents. Trade evolution does not imply NPC training or transfer of a world-owned individual.

The stock ingame_trade sequence is reused: species/egg eligibility, CreateInGameTradePokemon, DoInGameTradeScene, trade animation, friendship adjustment, mail/held-item behavior, Pokédex and trade evolution remain native. No link trade, server inventory or scarce stock exists. Stock table lookup is overridden only for index zero while this independent script owns its frozen descriptor; normal trades retain the original table. A declined or wrong-species selection clears the descriptor without creating or swapping Pokemon.

Request lifetime is 600 native transport pump ticks. Sequence, map, trainer, position and safe field checks reject stale responses. Native link sessions, battles, scripts and generated maps cannot start. Response freezes the offer before the first Yes/No; subsequent author closure or disconnect does not change it. The player can still decline. During the native script, disconnect reset preserves the descriptor until script exit. `/npc-trade cancel` cancels only a pending request; native choices are cancelled in their own menus. `/npc-trade status` distinguishes waiting/unavailable from a finished choice and does not invent a completed trade.

No server outcome is sent, no traded Pokemon is uploaded, and no NPC gains the player's individual. Save normally after the stock local trade. No new save flag, automatic save, persistence journal or cross-save transaction is added. Restart before saving follows ordinary unsaved-game behavior. This is not a durable exchange with a persistent NPC roster, not anti-cheat proof, and not a release feature.

Three component tests compile the actual new protocol/lifecycle code with the flag both off/on and the actual trade-definition accessor. They exercise stale/moved requests, bounded species, duplicate responses, timeout, cancellation, disconnect preservation, context exclusions, frozen identity and normal-table fallback. Source assertions cover actual chooser/confirmation/scene/evolution/Pokédex wiring. They do not execute the complete trade engine or assembly script. Full linked builds, rendered party and PC selections, cancel at both prompts, mail, held-item evolution, save/reload, disconnect during animation and ordinary/link-trade regression QA remain pending. Keep disabled until verified.

## App authoring

Independent app continuation of #429 (a78449301cb5823161c8274ca5669f2e8755d22a), not Maya #410. `world.configure_native_trade(requested, offered)` uses species names from discovery.native_trade_offers.species. Both empty strings close future offers. Only active world-owned characters author their own template; it is offered only when their current authority object is stationary and adjacent in an ordinary Hoenn map, not generated geometry. Existing residents are supported without canonical actor relocation. The NT protocol requires the current authenticated presence/link pair and fresh field state, and rejects a busy link or actor battle. It returns only species and map, no party or save data. Configuration history is not a trade result. Untrusted clients cannot report a completion through this protocol.

Build for development QA with `scripts/build_expansion.py --development --experimental-native-trades`. The normal build passes WORLD_TRADE_OFFERS=0. This flag is separate from nature battles. Fourteen focused authority/runtime tests cover a real populated resident, actor plan receipt, authenticated offer routing, adjacency/stale/busy checks, durable catalog, close, rejected completion reports and transaction rollback. Native and rendered QA limitations above remain.
