# Constraint-based connected regions (draft)

`world.generate_region_network` lets an enrolled world author choose topology and layout constraints rather than supply every room rectangle and passage. It is available to original-cast and generated-character plans. The agent supplies a literal label prefix and a bounded JSON `constraints` string:

- `places`: 2–4 distinct generated places.
- `rooms`: 2–4 rooms per place.
- `loops`: 0–1 independent cycle in the region graph.
- `branching`: maximum region graph degree, 1–3.
- `style`: rooms, rounded, organic or maze.
- `seed`: unsigned 32-bit integer.
- `corridor_width`: 1–3 tiles.

A deterministic binary partition packs room rectangles into each 31×31 interior. Seeded connected graph selection supplies room corridors and region passages, respecting the requested branching/cycle constraints. The established blueprint compiler produces and validates the actual native cave bytes. Identical arguments reproduce identical geometry; impossible constraints fail rather than silently change the requested topology.

The result goes through the existing region-network publication transaction. Admission installs real persistent selectable places and bidirectional passage props. Players with matching REGION1, prop and CAVELINK1 support select an entry place, enter using the existing cave entrance, and choose its passage interactions to reach neighboring places. The native transfer handshake and return-warp behavior are unchanged. Agents can subsequently populate, observe or navigate these actual identities using existing capabilities.

This creates supported plain caves, not outdoor regions, new artwork, a story, simulated exploration or encounter populations. It does not replace the shared destination or original Hoenn maps. The existing 850-character compiled-network budget remains: some combinations, especially four places with four rooms and longer labels, require fewer rooms or shorter labels. Existing world region/object/source capacities remain unchanged.

A staged request is not completion. If admission fails after opening the archive entries, those exact places remain available; reissuing identical arguments resumes the same network without duplicate places. Only the existing successful poll receipt claims installed connections. A new seed deliberately produces a different proposal, not an update to the old network.

Validation uses multiple seeds and styles, actual authority admission, native-shaped passage/ACK/arrival round-trip through in-memory client fixtures, distinct actor generation, failed-admission recovery, restart and unchanged shared-world checks. No live model, rendered game, full linked-native QA or seamless-overworld claim.

## Complete authored trainer adventures

`world.build_adventure(document)` compiles procedural geometry, new original trainers and an arbitrary authored branching battle campaign into a coherent discoverable adventure. This fills the gap between the geometry-only generator and the workshop, which installs graphs over already existing opponents. There is no installed story, prescribed roster, model call or random claim of victory.

The bounded JSON document contains `label`, the existing `constraints`, `trainers`, and `campaign`. Two to four trainer definitions specify a zero-based `place`, stable `id`, `name`, `role`, `goals`, supported native `team`, `gfx` and `text`. Every generated place must have a trainer, and every trainer must appear in the authored campaign. The initial graph uses ordinary `opponent`/`win`/`loss` nodes with arbitrary acyclic branches. It may revisit a trainer in different graph nodes, but does not change that trainer's team between stages. Larger documents use the existing blueprint workflow; the document limit is 6,000 characters and ordinary plan limits remain unchanged.

A deterministic placement search uses the generated seed and identity, excludes native entrances/exits and passage objects, and proves that all remaining floor tiles and an interaction tile beside each trainer remain reachable. Existing population, species, team, identity, collision and capacity validators still run. New actors receive real initial identities, not invented past experiences; no existing actor is moved or rewritten. Their future decisions remain independent and can change availability, so compilation is not a promise that the world will remain frozen forever.

Players select the named entry region through the normal region menu, enter by the existing native entrance and use the real bidirectional passages. They voluntarily start or host the published campaign through the existing board or `/guild campaign start ID` / `share ID`. The board now names an opponent's actual generated place and tile rather than only its reusable native map slot. Native challenges use the existing frozen opponent protocol and actual learned/owned party. Reports advance only each participating save's normal private run; they are client attestations, not independently verified victories. Native travel, return warps, shop/healing availability and optional battle consent are unchanged. No automatic healing, rewards, recruitment, story progression, party replacement or new region artwork is supplied.

Geometry and original cast are staged together through ordinary mechanic admission. Only after their exact admission is verified is the immutable campaign published. An interrupted or failed admission can leave named archived places, but not a falsely completed adventure. Reissuing the exact same authored document as the same author resumes those identities; a different seed is a different creation, not repair. Admission or publication conflicts fail without stealing another campaign ID, resetting actors or deleting retained places. A completed repeat returns the durable creation result without reapplying content. Public history records creation, not exploration or labor. Native saves are never changed by compilation.

They do not establish rendered native playability, autonomous model behavior, a full linked native build or a two-controller playtest. Matching experimental native features remain necessary; defaults and the integration candidate are unchanged.

## Authored field expeditions

The same creator now accepts optional `mechanisms` alongside zero to four trainers. This permits a full non-battle expedition or a mixture of learned-move interactions, alternate shared outcomes and native battles. There is no installed puzzle or prescribed sequence. The author supplies the actual state graph and campaign routes. Every generated place needs a trainer or mechanism, and every created trainer/mechanism must be referenced by the campaign.

Each of at most two mechanisms specifies `id`, zero-based `place`, two to four new `props` (`id`, `gfx`, `text`), and the existing linked-mechanism `program`. Each phase's object appearance uses `dx`, `dy`, `gfx`, `text`; the compiler binds offsets to deterministic generated anchors. The initial appearance must match the new props exactly. Subsequent appearances, move selectors, explicit choices, cooperation and transitions pass the ordinary mechanism validator. Props cannot claim existing identities, portable items or passage behavior. Existing standalone mechanism installation still requires nearby observation. Compilation can configure only the newly created props, not distant existing objects.

Campaign nodes may use ordinary `mechanism` plus `next`, or an `expedition` with alternative `resolutions`, as well as trainer battles. Author goals omit `definition`; the compiler inserts the fingerprint of the actual new mechanism and its exact region revisions. Nodes cannot refer to outside mechanisms. The existing 6,000-character document and plan limits remain; larger documents are assembled using bounded blueprint edits and a frozen blueprint result.

New places, population and mechanism definitions enter the same ordinary admission transaction. The immutable campaign is published only after exact admission succeeds. Failed admission resumes the same retained request. Repeating a completed creation does not reset mechanisms or NPCs. An interaction between admission and interrupted campaign publication can make exact verification fail; it does not rewind that interaction. Existing mechanisms, source capacity, occupancy, geometry and personal-save rules remain authoritative. Placement does not prove a puzzle is enjoyable or solvable with a particular player's party. A rejected layout requires revised author constraints, not an unsafe fallback.

Players find actual generated place names on the campaign board, select their entry region and travel normally. The existing move menu requires an eligible learned move and explicit confirmation. Shared object moves retain their existing client-report provenance and do not consume battle PP. Real object changes persist for other visitors. Campaign witnessing requires a new committed change after readiness, nearby fresh presence, and separate participation by every party member. It does not claim that a witness caused the change. An outsider may change a public mechanism first; the party may need an authored reverse transition or to leave. Cancellation leaves the shared world as it stands. No automatic reset, rewards, shared party, save progression or new native feature is introduced.
