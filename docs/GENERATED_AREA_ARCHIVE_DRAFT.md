# Saved generated areas for local hosts

This draft lets a local desktop-hosted world retain multiple generated caves and outdoor areas rather than losing the prior one when the host replaces it. The existing owner-authorized replacement transaction atomically saves the active template and, for desktop hosts with the archive enabled, retains each validated template by its full content identity. The first 80 characters of the host's description are stored locally as the area label. The host can refresh a list in the desktop launcher and activate an earlier area after confirming; everyone must leave the current generated area before it can change. Trainer saves remain independent.

Only one generated area is active at a time. This is not simultaneous multi-region travel, and the user cannot delete or export archived areas from this UI yet. Standalone server and remote hosted-service defaults are unchanged. Existing persistent local worlds migrate their current generated cave into the archive on host startup. Invalid or tampered archive entries are rejected on activation; storage failure rolls back the active-map write and leaves the current area unchanged. The archive and labels are in the local world's private SQLite database, not sent to other players.

Tests use the real authority and SQLite in memory/local temporary storage without binding sockets. They cover migration, multiple saved area identities, switching and restart, occupied-area refusal, tamper rejection, atomic rollback, trainer-save isolation, host selection and confirmation. No real desktop GUI interaction, live model request or two-client game session was performed. Parent experimental gates and multiplayer integration limitations remain.
