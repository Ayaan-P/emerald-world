# Long-lived original-cast experience

Independent follow-on to app #286. Existing native #26 pin is unchanged; this
candidate neither changes vanilla scripts nor depends on later movement drafts.

## Missing connection addressed

Public cast relationships and goals already cited actual events, but a later
author turn normally fetched only its new trigger. Once an earlier encounter
left recent history, the actor could retain an opinion without retrieving its
actual basis. This candidate automatically recalls retained episode and existing
relationship evidence from exact committed history before the real author turn.
It adds no affinity score, predetermined arc, fake training or new player chore.

## Author behavior

The typed `canonical_actions` record accepts optional `memories`, up to six
entries: stable id, one or two exact public event sequence IDs, and a literal
interpretation up to 240 characters. A new or revised interpretation must cite
its sources in that decision's eligible inspected evidence. Unchanged memories
survive later turns and restart without reauthoring their source. Authors can
revise or drop them; historical events are never rewritten.

The normal reaction preparation fetches these exact public records, plus the
sources of existing directional relationships, at the inspected world boundary.
Missing records, wrong-world replies, overlarge sources and out-of-bound IDs
fail closed. Only accepted public world history is used, never private trainer
conversation/save tables. Character interpretations remain explicitly tentative
fictional assessments, not objective truth, reciprocal feelings, permissions,
operator instructions or proof that a planned action happened.

The configured author sees both the earlier record and the new trigger. It can
retain or change its outlook and choose any already supported action. It still
must cite the actual new trigger and pass normal actor/version/action admission.
This does not grant access to arbitrary historical events or automatically
execute a model result. No live provider was invoked while developing it.

## Player experience and validation

Later ordinary original-NPC dialogue uses the resulting authored response as
before, alongside the actor's unchanged original scripts/services. At that
actor, `/guild cast ACTOR experiences` shows its selected public interpretations
and source event IDs. Private `memory` and `forget` commands remain separate.

The end-to-end regression executes Rydel's real shared project action, has Wally
retain that experience, advances more than a recent-history window of actual
public gameplay results, and restarts authority. A new public result schedules
Wally's normal author turn. Preparation retrieves the older source; a deterministic
author response fixture then commits Wally's actual assigned project action,
changes available player opportunities and updates the existing original-Wally
CORE response. No player story record, duplicate NPC, save flag or fabricated
physical action is created. This tests the real authority/typed author pipeline,
not live model judgment or rendered gameplay. Maya handles integration and QA.
