# Shared generated outdoor areas (draft)

This extends the generated-world authority to support outdoor `EWGMAP06` areas. The authenticated host validates and distributes the full 63×63 layout; CAVE6-capable native clients verify its digest and geometry before staging and acknowledging it. Both clients see the same generated land, grass and blocked water. Existing map music and Route 101 encounter table are used; the format does not yet include custom outdoor wildlife or generated art. Older clients receive `CAVE NONE` for an outdoor area, while newer clients fall back through prior versions when connecting to old hosts.

A local desktop host can describe an area and choose **Generate shared wilds**. The launcher asks for confirmation that the description is sent to the configured provider and may incur charges. An owner may instead explicitly run `python3 -m world.author_cave 'islands and grassy paths' --shared-wilds --admin-socket /path/to/admin.sock`. Model output is bounded data, not executable code. Only one generated cave or outdoor area is active at a time; everyone must leave it before an owner replaces it. Local desktop hosts persist the selected area across restarts. Ordinary players cannot publish a replacement.

A client reconnecting to the same verified area can stay inside. A different layout or a cave/outdoor change is staged only after return. Shared-map presence is accepted only for the map type and identity currently approved by the authority. Fly-to-friend and shared interactions are excluded inside generated instances as before. Existing simultaneous entry/return and peer-capability integration issues still need resolution. Tests use real native parsing, staging and bridge components with in-memory authority and a mocked model, not a live provider or two connected game clients; the native visual/movement test in CI is offline.
