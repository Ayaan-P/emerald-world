# Experimental model-authored offline cave wildlife

This draft adds a default-off `GENERATED_CAVE_WILDLIFE=1` native path for custom offline generated-cave encounters. An `EWGMAP03` template contains the existing bounded geometry, one visual profile, an encounter rate, and exactly 12 wildlife slots. Each slot holds a canonical current-engine species ID and a fixed level 1–100. The engine applies its existing land-slot weights: 20, 20, 10, 10, 10, 10, 5, 5, 4, 4, 1 and 1 percent. The selected visual profile determines existing cave art; custom species and levels are independent. This uses the 386 species already supported by the current vanilla engine, not a newer National Dex or newly generated creature art.

An explicit model call can produce a template with `python3 -m world.author_cave 'a cave of water Pokémon' --offline-wildlife-output cave.bin`. It sends the supplied theme to the configured provider and may incur usage charges. The pinned, tool-disabled model returns bounded data only; the compiler validates canonical species names, slot count, levels, encounter rate and geometry. It writes a new file exclusively, never overwrites an existing output and never publishes it. Build with `GENERATED_MAP_READY=1 GENERATED_MAP_AUTOTILE=1 GENERATED_CAVE_PROFILES=1 GENERATED_CAVE_BIOMES=1 GENERATED_CAVE_WILDLIFE=1`, then use `--generated-map cave.bin` offline.

The native loader independently validates the complete version, size, profile, wildlife and geometry before staging. It rejects eggs, old placeholder species IDs, invalid levels and rates. A new template clears the previous custom roster; the roster is available only in a prepared offline generated cave. Ordinary land encounters and Sweet Scent use the custom table and preserve their existing encounter/repel rules. DexNav is intentionally unavailable while a custom wildlife table is active because its current UI reads compiled map tables. Other special encounter methods are not claimed. The shared authority and older clients reject v3 templates; shared custom wildlife requires a separate negotiated protocol and has not been implemented.

Component tests cover the real native loader, wildlife validation/lifecycle, native encounter dispatch, DexNav gating, model mock, file formats and 386-species catalog against the engine header. The dedicated CI workflow builds the gates and attempts a real offline native encounter from a deterministic custom Magikarp roster. Inspect the exact-head CI result; no real model call, multiplayer custom wildlife, balance testing, full National Dex or human graphical playthrough has been performed.
