# Optional modern gameplay settings

This source candidate is based on RC3, not main. On native builds, World > Party EXP toggles a per-save flag. OFF retains the normal held-item EXP Share behavior. ON gives participating conscious Pokemon the ordinary shared participant base and each other conscious non-Egg party member half the base, before the existing trainer, trade, and Lucky Egg multipliers. The held EXP Share does not add a second award when the option is ON. EV and level-up handling use the existing native reward pipeline. Save normally to persist the setting.

World > Reusable TMs is a separate, default-off per-save setting. ON keeps an owned TM after a successful teach; it does not create items or change move compatibility. HMs remain reusable as before. OFF preserves original one-use TM behavior. Save normally to persist either toggle.

The co-op engine defers rewards until each trainer's private party is restored, and this same EXP command then runs per trainer. NPC-partner battles deliberately retain vanilla rules because they use a mixed party. Link PvP and other no-EXP modes retain their existing exclusion. The setting uses previously unused system flags 0x8E9 and 0x8EA; recheck all concurrent and later save-format changes before integration. Old saves with a nonzero unused flag may start enabled. No server or partner save is written by the toggle.

Focused C tests exercise the actual EXP calculation and award-dispatch cases and the successful TM-teaching path with isolated stubs, plus helper arithmetic and source wiring. They are not a native build, graphical UI test, co-op acceptance, or evidence of safe progression in a real save. Before release verify the actual option UI, default-off behavior on clean and imported saves, participant/bench/fainted/Egg/full-level/held-item/trainer cases, NPC-partner behavior, both co-op owners including no-participation masks, interrupted battles and save/reload, repeated TM use, cancelled and failed teaching, held items and bag save/reload, and flag conflicts in the combined candidate. This branch does not claim playable acceptance.
