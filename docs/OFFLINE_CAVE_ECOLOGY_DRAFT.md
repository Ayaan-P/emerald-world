# Experimental model-selected offline cave ecology

This draft introduced an opt-in offline encounter profile; the successor adds negotiated shared profiles. A versioned `EWGMAP02` template contains a single bounded profile byte plus the existing validated 31×31 geometry. Profiles select existing compiled vanilla encounter tables: granite (levels 6–10), meteor (14–20), ice (26–32), or victory (36–40). The default `EWGMAP01` file and shared-world cave protocol remain unchanged. Old clients cannot enter profile-enabled shared caves. A newer authority and client can negotiate the profile-aware shared format; see SHARED_CAVE_ECOLOGY_DRAFT.md.

To opt in, build with `GENERATED_MAP_READY=1 GENERATED_MAP_AUTOTILE=1 GENERATED_CAVE_PROFILES=1`. A user can export an existing validated proposal with `python3 scripts/export_generated_cave.py proposal.json cave.bin --encounter-profile meteor`, or explicitly ask the existing pinned, tool-disabled author command to create a new offline template with `python3 -m world.author_cave 'a meteor-themed cavern' --offline-output cave.bin`. The latter sends the supplied theme to the configured model provider and may incur usage charges. The model may select only one of the four predefined profiles; it cannot provide executable code or arbitrary species/levels. The command does not publish the file and will not overwrite an existing output. Start the gate-enabled native client offline with `--generated-map cave.bin`.

The native loader validates the version, exact length, bounded profile and entire geometry before accepting a template. Selecting a new template resets the previous profile; profile lookup uses existing compiled encounter data inside a prepared offline cave or a verified profile-enabled shared cave. Ordinary maps and legacy shared caves retain their prior lookup. The art remains the existing cave tileset regardless of the profile.

Component tests compile the actual native template loader, profile lifecycle and wild-header selection, exercise gate-off rejection, invalid data and profile reset, check all selected encounter tables exist, and mock the model author. The dedicated CI workflow builds all three cave gates and adds an actual offline native encounter check for the meteor table. No real provider request, multiplayer profile synchronization, custom Pokémon generation, balancing or human graphical playthrough is claimed. Inspect exact-head CI and the parent drafts before enabling.
