# Experimental native tile bank for world actors

Stacked on #171. The stock renderer has 1,024 OBJ tiles in 32 KiB of graphics memory. `WORLD_NATIVE_TILEBANK=1` is a separate default-off PC experiment that adds another 1,024 tiles and expands the portable VRAM backing from 96 KiB to 128 KiB. It requires `WORLD_EXTENDED_OBJECTS=1` and `WORLD_NATIVE_OAM=1`; invalid combinations fail at compile time. The GBA path and original save data are unchanged.

The extra allocator is scoped to world-bridge sprite creation. Ordinary game sprites continue to use the original bank. If the extra bank is full, a world actor falls back to the stock allocator. Animation copies use the full extra tile address; copied sprites, including reflections, retain a reference to the same allocation until the last copy is destroyed. On final release, queued frame copies overlapping that allocation are removed before the tiles can be reused. An extra-bank sprite is emitted into native OAM slots 128–190 with a bank marker; a hidden metadata record in slot 191 lets the PC renderer reconstruct the original sorted order against normal sprites. Invalid ordering metadata falls back to physical OAM order. While extra-bank actors are visible, 191 of the 192 native OAM entries are available for display. This does not increase palette or affine-matrix limits.

Local component tests compile production functions and the actual software renderer with disposable fixtures. They cover allocation, exhaustion, fallback conditions, refcounted sprite copies, pending-copy cancellation on final release, real sprite creation/animation copy/destruction, native OAM placement, a pixel read from tile 1,024, original-bank isolation, ordering/priority across banks, all metadata merge boundaries, malformed metadata and unchanged GBA/structure limits. Related capacity, OAM, save-isolation and co-op fixtures pass locally. This is not a real native build or graphical/multiplayer playthrough. Manual OAM/VRAM operations, reflection and animation lifetimes, allocation pressure, scene transitions, deep ordering, resource exhaustion, old saves and multiple real clients need native acceptance. A dedicated CI job builds all four gates and runs the ordinary standalone headless frame/save smoke without changing golden frames; inspect its result before enabling. Never treat this as unlimited sprite graphics memory or a verified 32-player session.

The first CI native build completed, but its standalone smoke failed the unchanged frame hashes in ordinary scenes: the no-extra-sprite fallback had left its loop index at the end of the array. The current source resets that index and has a production-emitter/renderer regression for both no-extra and lowered-OAM-limit paths. It also cancels queued copies on final extra-tile release before reuse. Re-run CI on this exact head; the local regression is not a replacement for the full smoke.
