# Experimental model-directed cave styles

This draft builds on the shared generated-cave proposal. The blueprint accepts three optional, bounded fields: `style` (`rooms`, `rounded`, `organic`, or `maze`), unsigned 32-bit `seed`, and `corridor_width` (1–3). Omitted fields retain the previous rectangular-room output exactly. The opt-in model author is prompted to choose these fields, while older valid model responses still work. Organic edges and per-room mazes use deterministic SHA-256-based choices; the same blueprint produces the same geometry without calling a model. All room centers remain connected to the authored room graph, the fixed spawn and exit remain reachable, and disconnected decorative pixels are removed.

The output remains the existing inert 31×31 wall/floor cave template. It uses the existing cave tiles, protocol and optional host publication path. It does not generate art, new tilesets, routes, NPCs, encounters, a story or multiple regions. A model call still requires the existing opt-in setup, sends the theme to its provider and may incur usage charges; no live model call was made here. Publishing still requires the existing explicit owner action and the shared-cave safety checks.

Tests exercise hundreds of varied graphs for every style against both the production exporter and authority validator, plus 200 maps against the actual native C staging function, deterministic results, seed diversity, limits and malformed model responses. The original four-field schema is preserved. These are component checks, not a native build, graphical evaluation, live model run, real multiplayer or gameplay acceptance. The parent draft's integration and safety limitations still apply.
