# Shared generated outdoor guide

This draft extends the guided outdoor template to shared generated areas. A CAVE7-capable client receives the same 63×63 geometry and bounded guide appearance/dialogue as every other compatible client. The SHA-256 identity binds the full map and guide metadata. The host validates the literal text and path around the guide, and each native client validates again before staging. The authority and client both reject player positions on the guide's occupied tile. Changing only the guide's dialogue or appearance changes the identity; a trainer inside must return before a changed area is staged. Reconnecting to the identical area preserves the current guide.

The local host launcher offers **Wilds with guide** with explicit provider/cost confirmation. The owner may also explicitly run `python3 -m world.author_cave 'friendly islands' --shared-guided-wilds --admin-socket /path/to/admin.sock`. Both send the description to the configured model provider and may incur charges. Model output contains only bounded geometry and literal text, not executable code. Local desktop hosts retain the area in their generated-area archive. CAVE6 and older clients receive CAVE NONE for this format; CAVE7 clients fall back to prior protocol levels on older servers.

The guide uses an existing sprite and fixed native interaction script, with one or two short model-authored literal lines. This is not a quest system, trainer battle, generated artwork, or free-form conversation. Automated native guide interaction in CI is offline; shared behavior is tested with the real C bridge/wire and an in-memory authority, not two connected game clients. No live provider call or human playtest was performed. Existing simultaneous entry/return and peer-capacity integration issues remain.
