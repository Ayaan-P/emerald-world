# Experimental matching trainer appearances

When `WORLD_MATCHED_TRAINERS=1` is enabled alongside `WORLD_EXTENDED_OBJECTS=1` on the native client, world-bridge peers can use their own Brendan or May walking and bicycle graphics when their graphics request the same reserved player palette as the local player's current graphics. They share the existing palette rather than loading a remote palette over it. The feature is off by default. Surfing, field-move graphics, incompatible palettes, missing players and unsafe IDs fall back to the existing generic trainer behavior.

The object-event spawn path independently rejects a world-bridge player-palette request if the palettes do not match, and does not reload the local player palette for a matching peer. Normal game-created objects keep their original palette-loading path. Reconciliation re-evaluates the match as either player's graphics change; it replaces an existing remote immediately when the allowed appearance changes. This experiment does not expand palette capacity or solve different-gender/custom palettes, remote walking animation, surf mounts, graphical effects or protocol state synchronization. It must not be described as full avatar parity.

Component fixtures compile the actual compatibility, object spawn and bridge reconciliation functions, checking matching and mismatching palettes, inanimate/invalid graphics, player disappearance, changing local palette and sprite replacement, creation failure and prevention of local palette overwrites. A dedicated CI workflow builds all five experimental gates and runs the standalone headless frame/save smoke unchanged. It does not replace live multiplayer and graphical testing, which remain required before integration.
