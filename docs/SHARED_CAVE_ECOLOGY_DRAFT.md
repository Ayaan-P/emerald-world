# Experimental shared generated-cave ecology

This draft extends the offline profile format to the shared generated-cave authority. A profile-enabled template is `EWGMAP02`, a bounded encounter-profile byte and the existing 31×31 geometry. Its SHA-256 identity covers both profile and geometry. The authority distributes it only to clients that negotiate `CAVE2`; their native parser validates the version, profile, row framing and digest before staging. Valid profiles select existing compiled Granite, Meteor Falls, Shoal Cave ice or Victory Road encounter tables. This does not generate arbitrary species, levels or artwork.

Legacy cave clients can still use v1 caves. If the authority currently hosts v2, it replies `CAVE NONE` to v1-only clients rather than admitting them with a different encounter table. New clients retry v1 negotiation with an older authority, and then fall back to the prior non-cave role if needed. On a profile-only or geometry replacement, the authority changes the content identity and invalidates acknowledgments. A reconnecting client inside a different profile must return before staging and acknowledging the replacement. The existing owner-only publication, occupied-cave refusal and optional persistence remain in force.

An owner may explicitly publish a model-authored profile with `python3 -m world.author_cave 'meteor cave' --admin-socket /path/to/admin.sock --shared-ecology`. This makes an opt-in model call, sends the supplied theme to the configured provider and may incur usage charges. The model can select only one of the four bounded presets; no model-generated code is executed. The host may instead publish an existing validated v2 file with the existing publish command. Both clients and server need the corresponding changes and cave/profile build gates; defaults remain off. The network transport and peer-count capability work in other drafts still need reconciliation.

Tests cover actual in-memory authenticated authority dispatch, old/new capability behavior, profile-only reset and persisted restart, SHA binding and tamper rejection with the production native parser, native fallback negotiation, and a real native bridge/staging fixture that returns before changing a profile. The inherited CI workflow also builds the actual native client and runs offline gameplay tests. These are not real two-client native sessions, live provider calls, WAN tests, a human graphical playthrough or proof of safe simultaneous cave admission. No user save is used by CI.
