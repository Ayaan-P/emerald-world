# Natural-language host world goals

Stack on PR308 (actor-landscapes); native pin remains PR32
30a4fae1b19340225926d350895a30e516615a8c. No new map admission or native code.

In the local Expansion host's Living cast agents panel:

1. Select/configure Claude or OpenAI as before. Keys stay in the host environment.
2. Choose an existing active world goal actor. Original cast enrollment is still
   separate; this feature does not silently create a character or replace a canon NPC.
3. Describe the desired world-building outcome and queue it with the existing
   explicit author authorization. No provider is started by submitting a goal.
4. Start the author if stopped. The actor receives the discovered capability
   catalog, current state, host goal and exact existing public evidence. It can
   compose a typed plan or wait. Real receipts schedule subsequent author turns.

This is a natural-language entry into existing capabilities, not a new set of
prescribed scenarios or a raw Python prompt. Configured providers return typed
single-actor changes and tests; normal compiler, staging and sandbox requirements
remain intact. Host goals are requests, not fabricated events or achievements.

Each request has a stable client ID. Double submits do not duplicate work; the
same ID cannot be reused with different content. Busy actor author turns refuse
new goals. Submission explicitly replaces that actor's followed purpose; it does
not itself cancel an executing world plan. UI statuses describe author requests,
not claimed completion of world actions. Use actual receipts for those outcomes.

Stop world goal follow-up stops subsequent author reactions and interrupts queued
turns. It cannot undo committed world changes or stop an already committed plan.
Stopping the author preserves queued work; it does not cancel existing authority
execution. No automatic provider start, retries, secret fields or remote-host
control. Public fictional context and the entered goal go to the selected
provider; private player memories and live party data are excluded from this turn.

Validation: real launcher action/queue, both official provider parsers with fake
API transports, typed compiler/admission, actual place creation, receipt-driven
next turn and a revised stopped plan. UI tests cover explicit queueing and double
clicks. This is not a live API call or full sandbox-backed model run; the existing
full-worker sandbox tests remain separately reported. Maya handles rendered
launcher/native integration and release QA.
