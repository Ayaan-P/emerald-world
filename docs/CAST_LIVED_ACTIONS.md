# Encounter-driven original actor intentions

Stacked follow-on to app #294, using the same native #29 pin. No additional
native payload, fixed plot, automatic model start, or story/service mutation.

## Connected experience

An enabled author may retain an intention with kind `scene`, target equal to
its own reviewed scene key (`rydel_step` or `steven_study`), and a stable ID.
The actor's existing goal, literal dialogue and optional activity-project
requirements explain why it wants to act. No new agenda is installed by default.

After a player talks to that original NPC and returns to ready field control,
the authority offers the retained activity when the existing complete cohort
can safely participate. Players need not discover and type `scene ask` first.
Everyone still chooses `/history scene join` or cancel. The invitation explains
that completed actor activity enters shared history without player names.
Declining does not repeatedly prompt during that connection. A new session may
encounter the retained plan again. No player is made to perform an errand.

The native paired runner performs real held-movement steps, all observers report
each barrier, and every original actor must return home. Only that full path
records `canonical_scene_observed` and consumes the intention. Cancellation,
interruption, missing observers, timeout and restart recovery are not success.
Old scenes without retained intentions keep their existing history behavior.

The public receipt records actor, authored version, intention, reviewed path and
step count. It contains no player names, save IDs, private conversations, attitudes
or claimed achievements. It is explicitly cohort native attestation, not
anti-cheat proof. It proves neither successful research nor training nor travel.

The existing character reaction queue can use this actual event. The actor can
revise its goal, retire the completed intention, and choose an already supported
world action. Another actor with an existing directional relationship can also
interpret it, without inferring friendship or agreement. No reply or action is
fabricated by the runtime. Actor interpretation and subsequent project choice
still require the configured author; no live model was called in validation.

## Tested full connection and limits

The regression creates a retained Steven intention through the actual typed
compiler, talks at his original house, auto-offers, and runs two compiled native
controllers through four steps and home restoration. The actual public reaction
queue receives the event. A deterministic author response fixture then commits
an assigned shared project action, making an existing player-facing opportunity
available without player completion or changes to player records.

This is the actual authority/C-controller pipeline with engine doubles, not a
rendered full-engine demonstration or autonomous town roaming. Full linked build,
rendered multiplayer timing and original story/service regression remain Maya's
integration/QA responsibility. No merge or release is performed here.
