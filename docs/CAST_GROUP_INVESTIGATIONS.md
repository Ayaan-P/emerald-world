# Canonical cast group investigations (separate candidate)

Branch `dot/coop-field-mysteries` is based on consolidated living-cast app
`f81be46b6d9296e2710563af5878b3d4500b0b4e`, not an update to PR286. It retains
native pin `f5b45730ef96debf512f501109b3388ab2342cc6` and needs that paired
original-actor/project UI. Maya owns integration, native QA and release.

## Connected player experience

An enrolled existing cast agent can publish an optional `investigation` from
actual permitted history or its committed goal, with two to four distinct roles.
This is authored research/puzzle content, never a fabricated canonical discovery,
legendary encounter, reward or main-story flag. Initially the station catalogue
is exactly the four previously reviewed ordinary Petalburg/Rustboro positions;
this does not claim new-region/native-map support.

Talk to the original character, then use `/guild cast ACTOR investigate` for the
actual investigation and numbered roles. `/mystery start PACK ROLE` starts a run;
partners use `/mystery join CODE ROLE`, or omit ROLE for a free slot. The starter
can choose any role. The last role is the solver, so solving is not tied to host
ownership. The invitation stays open until every required role has joined.

Players explore normally, potentially on different maps. At their respective
stations they request `/mystery clue`, discuss the clues privately using existing
communication, and the solver submits `/mystery solve STAGE ANSWER`. Everyone
must have read their own clue and be freshly ready at their station. No warp,
party change, battle redesign or save grant occurs. Leaving cancels the run;
restart retains membership/stage but requires fresh presence again.

Completion is private to participants. Return to the original actor: an agent's
player-facing initiative scene may use its own investigation as prerequisite, so
the existing START project panel shows the actual unlocked choice. An outsider
cannot claim it. The authored question must clearly identify any shared choice.

Only choosing that public project consequence emits an anonymous authority
receipt, which can cause the original character to revise a goal or take a
supported action. Reading clues and solving do not publish trainer names,
answers, private completion or campaign progress. Actor-only scenes cannot read
private mystery state. Legacy projects retain their previous privacy behavior.

## Author/authority contract

- `investigation` uses the existing immutable mystery pack schema, now 2–4 roles.
  Every stage has one distinct reviewed station per role, within actor interests.
- A player scene in the same actor's `initiative` may set
  `mystery=investigation.id`; other/private prerequisites remain forbidden.
- Investigation and initiative publication commit atomically with the actor
  record. IDs cannot change owners or content; capacities remain bounded.
- Shared-choice consequences and their public receipt are one transaction.
  Replay returns the original choice receipt without another publication.
- These are client-attested positions under the existing trust model, not an
  authoritative physics simulator or a reward-security boundary.

## Verification boundary

The deterministic fixture publishes an actor-owned investigation, assigns four
real authenticated peers different roles, reads separate clues across two maps,
rejects stale presence, completes privately, returns to the real original-actor
PROJECT authority handler, rejects a nonparticipant, commits one explicit shared
choice, and drives that actor's next evidence-based version. Restart preserves
completion and authored state. Existing two-player mysteries stay compatible.

No fixed investigation is auto-installed; the fixture is test-only, not a live
agent output. No new native payload is published. Full rendered four-client UI,
model content quality, live author flow and ordinary-story acceptance remain
Maya's QA. Optional puzzle commands use existing native/server support, not a
claim of new synchronized cutscenes or arbitrary multi-region content.


## Follow-on save isolation

Canonical cast investigations now bind each participant to their active native save lineage when joining. Switching saves cannot provide station occupancy, read that save's clues, cancel its active run or reuse its completion in the original actor panel. Returning to the enrolled save restores access, including after authority restart. Trainers may have separate investigations in separate saves.

Existing unbound canonical runs/completions are preserved but cannot be assigned a reliable lineage retroactively. They do not unlock canonical project choices; replay from the intended save is necessary. Ordinary non-cast legacy mystery packs keep their existing trainer-wide scope. No canonical flags, player saves or prior shared-world consequences are changed or revoked. Shared project effects already committed remain shared world state, distinct from the save-specific eligibility that permitted them.
