# Isolated companion practice evaluator (not live training)

WorldCharacter_EvaluatePractice evaluates a bounded daycare-style exercise on a copy of a Pokemon. It accepts 1..1024 simulated steps and an NPC-specific level cap. Each step contributes one experience point, using Expansion's actual species growth table, level calculation, move-learning and stat routines. Identity, IVs, current moves and other Pokemon fields start from the source copy. Native daycare-style move replacement applies on gained levels; this is not species evolution.

This is an isolated host-worker candidate, with **no gameplay caller, server reward path or autonomous training scheduler**. It does not prove walking, battles, victories, time spent, or an actor's canonical story progression. It must run in an isolated native worker process, not during live gameplay: native move-learning routines use global scratch state. Source and destination cannot be entries of either live party, and source cannot equal destination. Failed input leaves the output untouched.

The evaluator intentionally does not use TryIncrementMonLevel: that routine reads the current player's badge-dependent level cap. An NPC job supplies its own bounded cap. No player save or progression is read or written here. Original Wally/Steven teams are unchanged; their scripted species, IVs and moves must not be replaced with dynamic defaults or called earned growth.

Before this can produce persistent earned NPC growth, integration needs:

1. A trusted host-owned practice job, bounded by a character intention and runtime budget, with frozen companion identity, full Pokemon state, source revision and exercise terms.
2. Full linked validation of the new isolated native mode that restores only the NPC snapshot and returns full state. The mode and host adapter are now implemented below; current tests use explicit engine fixtures.
3. Integrate the independent transactional host ledger with live authority once per job, rejecting stale or changed identities. Player battle-result packets and agent assertions must never substitute for the worker receipt.
4. A companion transport/storage extension retaining accumulated EXP and learned moves. Existing CHARPK1 only transports species/level/personality/owner and recreates level moves; silently using it would lose practice state.
5. Full native tests/build and rendered QA before live integration. Do not automatically start this worker or infer completed training from a queued job.

Validation performed: host compilation of the production evaluator, exact published native experience tables and GetLevelFromMonExp across all six growth curves; checks cap saturation, identity retention, unchanged source, party protection and bounds. Storage, move-learning and stat APIs are test doubles in that host test. Two native TEST cases are supplied for the complete Expansion test runner but have not run here. Current workspace lacks SDL2 and the current paired checkout is component-only. No full native simulation or gameplay claim.

## One-shot worker and durable host ledger candidate

The executable now recognizes `--character-practice` before the platform's normal console/player/save startup. It reads exactly one bounded request from stdin and exits. `INIT1 species level personality owner` creates a fictional IV15 Pokémon under a private zeroed creation context; `STEP1 sizeof steps cap hex` evaluates an existing snapshot. `STATE1 sizeof species level personality owner exp hex` returns every byte of the native Pokemon, preserving learned moves, EXP remainder and other fields instead of regenerating by level. Encrypted checksums and bounded species/moves/EXP are checked before use. No file path or player save is accepted by this mode.

Opaque snapshots are strictly executable-specific, not interchange/save files. The paired app `world.companion_practice` pins the executable SHA256, invokes it in a temporary working directory with a minimal environment and timeout, and records independent fictional companions and one-shot jobs in its own SQLite ledger. A job freezes full state, source revision, exact binary, steps and cap. Completed state applies atomically only to that unchanged source. Wrong identities, increased EXP beyond the job, stale sources, cancelled jobs and replay are rejected. A crashed process leaves a running job for explicit operator inspection/cancellation; it never retries automatically.

This operator-facing ledger is separate from live server state. It is **not yet connected to canonical character intentions, dynamic battles, or player clients**. CLI: `python -m world.companion_practice --db NPC_ONLY_DB --engine VERIFIED_BINARY --sha256 EXACT_BINARY_HASH init ACTOR INDIVIDUAL SPECIES LEVEL PERSONALITY OWNER`; `practice ACTOR INDIVIDUAL STEPS CAP` queues; `run JOB` executes; `show ACTOR INDIVIDUAL` inspects; `cancel JOB` cancels. Do not use a player save as the database. No binary is automatically downloaded, selected or trusted.

Process-boundary validation compiles the production request parser/evaluator plus actual experience tables and level calculation with explicit fake Pokemon storage/move/stat APIs, then executes it through the real pinned Python subprocess adapter and persists/reopens the ledger. This does not establish that the full linked Expansion executable works in early-entry mode. Full build/runtime validation remains mandatory before use, particularly native initialization dependencies; the current environment still lacks SDL2 and a current full paired tree. No live training, original Wally preset fidelity or earned victories are claimed.

## Retained cast intention dispatcher

Canonical actors may now retain `{id, kind: "practice", target: REGISTERED_INDIVIDUAL, reason}`. The typed author compiler validates the intention; it does not claim execution or rewrite an original team. A dedicated read-only admin response returns only world ID and cast versions/practice intentions, omitting player identities, save paths, parties and private conversations.

After Maya validates the exact full native binary and its roster provenance, the operator can run `python -m world.cast_practice_worker --db NPC_ONLY_DB --engine VERIFIED_BINARY --sha256 EXACT_BINARY_HASH --socket ADMIN_SOCKET --validated-native --steps 256 --cap 20`. The switch is a deployment QA gate, not a player consent toggle. No worker starts automatically, and no roster is automatically created. Register only an independently verified fictional companion; current INIT1's IV15 defaults must not be presented as original Wally's story presets.

One invocation handles at most one retained intention. It requires that actor's existing companion under the same executable hash, freezes the actor version and exact intention, and checks again before and after native evaluation. A changed/withdrawn intention discards the result. Intention claim and practice job creation are atomic in the independent ledger. Eight attempts per actor/world bound this candidate; interrupted or failed tasks are not automatically retried or migrated. Duplicate task IDs cannot retrain repeatedly, including after restart.

The receipt records the exact job, engine, source/result revision and snapshot hashes, simulated steps, EXP delta and levels. It is explicitly `local_host_ledger_only`. The live world, original party and public history remain unchanged; the author cannot mark practice fulfilled using this staged path. Reconciliation/public result delivery and native full-state battle consumption remain future integration gates. Do not describe a pending intention or local fixture result as completed live-world training.

Tests exercise actual typed canonical authoring, real authority admin dispatch, registered/missing roster, QA gating, one-shot ledger completion, restart, withdrawal during evaluation and refusal of fabricated public fulfillment. Native evaluation in these authority tests is a deterministic test double; the separate component test exercises the production protocol in a compiled process with explicit Pokemon API fixtures.
