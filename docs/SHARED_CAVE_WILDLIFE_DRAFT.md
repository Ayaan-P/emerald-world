# Shared authored cave wildlife (draft)

This opt-in successor to the offline wildlife draft distributes a single bounded `EWGMAP03` cave to capable world clients. Its SHA-256 identity binds the visual profile, 12 weighted wildlife slots, rate and geometry. The authority validates species and levels and only offers the template to clients negotiating `CAVE3`. Older clients get `CAVE NONE`, not a differently populated cave. Newer clients fall back to `CAVE2`, `CAVE`, then the legacy world protocol when an old host rejects a capability.

An owner can explicitly author and publish a shared template with `python3 -m world.author_cave 'a cave of water Pokemon' --admin-socket /path/to/admin.sock --shared-wildlife`. This sends the theme to the configured model provider and may incur usage charges. The model supplies bounded data, never code. Both host and clients need the relevant drafts; native clients additionally need `GENERATED_MAP_READY=1 GENERATED_CAVE_PROFILES=1 GENERATED_CAVE_WILDLIFE=1`. The biome and autotile gates remain separately optional. Wildlife selection is limited to the current vanilla engine's 386 species; DexNav is disabled while the custom table is active.

A wildlife-only replacement changes the identity. Clients in the old cave return before accepting the replacement; the host refuses replacement while the authoritative presence is inside. These checks do not solve all simultaneous admission and return issues. The expanded peer-capability handshake in the separate capacity work must be reconciled before integration. Testing so far exercises actual C parsing and gameplay state with in-memory authority and mocked transport, not two connected game clients; no live provider call was made.
