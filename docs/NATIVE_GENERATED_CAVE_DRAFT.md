# Experimental generated cave

This draft adds a native-runtime cave instance behind `GENERATED_MAP_READY=0`. It is an early exploration path toward generated tilemaps, not a shared world, an LLM integration, or a release-ready feature. The map and its generated IDs are appended to the existing registry; the feature flag disables entry and runtime replacement by default.

When enabled in a native build, the World menu offers **Explore generated cave** only offline, outdoors, and on foot. It builds a 31-by-31 connected cave in memory using the game's existing Cave of Origin tileset. Every odd cell belongs to a depth-first maze; a south-facing exit tile and World > Leave generated cave return to the exact field coordinates captured on entry. The previous dynamic warp is restored after return. A new entry uses a new local frame-derived seed. This is a simple deterministic maze algorithm, not art or content generated by an LLM.

The cave is deliberately empty. It has no NPCs, encounters, loot, stories, network identity, map-instance protocol, persistence or player-created proposals. Multiplayer entry is denied; different clients do not share seeds. Saving is suppressed while in the instance, including a guard at native save-file publication; the normal Save menu row is hidden. Quitting without leaving returns to the last existing save. Ordinary map transitions can still run normal game-time, field and roamer logic; complete preservation of every in-memory story or world state has not been proven.

`test_native_generated_map.py` compiles the production generator with disposable engine stubs, checks reachability and closed boundaries for 100 seeds, confirms different seeds yield different layouts, and exercises direct return plus the dynamic-warp return boundary. `test_generated_map_save_guard.py` tests the real normal-save entry point and native file-publication guard against stubbed storage callbacks. The exit-tile check reads the existing cave tileset attributes and verifies its south-arrow warp behavior. These are component tests; they do not simulate native rendering, actual movement or a real save/reload.

Before enabling or integrating: rebase the map group and layout IDs against the candidate; build the actual native client; check World menu, entry fade, camera, walking, cave graphics, exit arrow, return coordinates, old dynamic-warp restoration, Save suppression, soft reset/quit and disposable save/reload. Verify transitions don't change story state unexpectedly. Also validate every serialization path and field context, and test occupied or unsafe return tiles. A shared version needs an authoritative instance ID, stable blueprint/seed exchange, native transfer and validation, consistent peers/late joins, safe admission/return and persistence rules. The current local maze algorithm is not the Python generated-blueprint format and does not consume model output.
