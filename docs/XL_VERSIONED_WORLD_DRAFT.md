# Versioned offline XL story worlds

An agent can create a versioned world from a validated painted XL story file using `python -m world.xl_versioned_world create painted.bin world.bin`, then revise its blueprint and paint while preserving the world ID, characters and graph with `python -m world.xl_versioned_world revise world.bin changes.json world.bin --replace-output`. The revision is validated before atomic replacement and becomes visible on the next offline re-entry. The random 128-bit world ID plus exact graph and cast bytes identifies story progress; terrain changes alone retain it, while changing the ID, cast or graph starts separate progress. This is deliberate: agents can reshape a world without erasing its story, but cannot silently carry state to different dialogue rules. Concurrent revisions are last-writer-wins; there is no compare-and-swap.

Progress persistence remains explicit, POSIX-only and limited to the 64-entry FIFO sidecar. Windows remains session-only. This is offline only and does not add shared multiplayer state or live mutation of an occupied map. Native CI attempts to advance a story, replace terrain while the game is running, re-enter and then restart while preserving the story state and trainer save. Until CI passes, this game path is unverified. No real model call or visual review is implied. This draft stacks #226 and its predecessors; integration remains separate.
