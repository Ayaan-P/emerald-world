# Experimental remote movement presentation

`WORLD_SMOOTH_PRESENCE=1` is a default-off native visual experiment. When a visible human peer updates to an adjacent map tile, the bridge immediately keeps the server's destination as the actual object coordinate while temporarily offsetting its sprite and easing that offset by two pixels per native game frame. Known trainer graphics play a standard walking animation, then return to their committed facing. Reconciliation can run twice per frame but animation advances only once per game frame. Extra-fast accumulation is bounded; gaps, teleports and unsupported graphics snap to the committed position instead. Shared NPCs do not use this experiment.

This affects presentation only. Collision, interaction, telemetry and save isolation continue to use the authority's committed tile. The drawn trainer may therefore briefly lag behind its collision/interaction tile. A live multiplayer playtest must judge whether that tradeoff is acceptable, especially with lag, reversals, map transitions, camera scrolling, menus and different movement speeds. This is not client prediction, server reconciliation, authoritative movement validation, full remote animation synchronization or a claim of improved latency.

Component fixtures compile the actual bridge reconciliation and advance functions. They cover adjacent updates, once-per-frame advancement, authoritative coordinates, animation, teleport snapping, bounded reversal and avoiding slots reused by engine objects. A dedicated CI workflow builds all six optional gates and runs the unchanged standalone headless frame/save smoke. Actual graphical and multiplayer acceptance has not been performed.
