# Experimental extra runtime object slots

The stock save contains exactly sixteen object events. Raising the shared constant directly would change `SaveBlock1` and make old saves unsafe. This prototype separates that fixed serialized count from an opt-in 32-entry native runtime array. `WORLD_EXTENDED_OBJECTS` defaults to 0 and this is not a release-ready or native-tested feature.

With `PORTABLE` and `WORLD_EXTENDED_OBJECTS=1`, ordinary native objects and the local player still allocate only in the original sixteen slots. The world bridge attempts to allocate remote trainers and its shared objects from sixteen additional transient slots first, falling back to a free original slot if necessary. Thus a busy map can retain its normal campaign NPCs and still render some remote peers. The network relevance window remains eight peers and the native sprite and palette pools remain unchanged: this is not a claim of 32 players or unlimited entities. The save path strips bridge actors as before, copies only the original sixteen object entries and clears transient entries on load.

The gate-on and gate-off production allocator/save functions were compiled with disposable C stubs. Tests exercise allocation, full pools, duplicate identity checks, save boundaries, old save layout and clearing of transient slots. A separate compiler check compares the actual `SaveBlock1` size and following member offsets across both builds. Existing save isolation, native save and co-op engine component tests pass. Portable changed sources passed isolated syntax checking with placeholder generated graphics, not a game build. LeakSanitizer was disabled due to the local ptrace restriction.

Before enabling: audit all native object index assumptions, resource exhaustion, engine scripts and transitions; build the actual native client; verify old saves and new saves, dense maps, sprite/palette exhaustion, scene changes, saves, load/rejoin, native link and story scripts with real disposable clients. Test actual two-client rendering and late joins. The original sixteen-entry save format and per-trainer ownership must remain unchanged. This branch may overlap generated-cave work in `world_bridge.c` and `event_object_movement.c`; reconcile against the integration candidate. No native rendering, full build, real save/reload or multiplayer test has run here.
