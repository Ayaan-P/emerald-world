## Reusable activity loop

A followed Steven can use existing typed canonical actions to propose a public
guild expedition, revise his goal from its real attributed completion, retain a
question for another established actor, and execute it through existing bounded
initiative and delivered correspondence. No separate Steven quest script, fixed
arc or model startup was added. The author must be enrolled/configured using the
existing mechanism; an empty world does not receive a preset Steven agenda.

The integration test exercises production authority, explicit leader acceptance,
existing chronicle privacy, two actual authenticated visits, public completion,
reaction queue admission, changed goal, retained initiative, delivered letter to
Briney, one fulfillment receipt and restart. It uses deterministic author output,
not a live model. Letters are correspondence, not simulated physical meetings.
Expedition completion belongs to the guild, not Steven's own travels or battles.
No collected rocks, personal Pokémon, trainer victories or hidden memory are
invented. Existing opt-in private encounter/choice mechanisms are shared.

Native production-hook tests check refusal before the individual story gates,
battle refusal and timeout recovery. A full-source checksum regression verifies
that all unrelated house scripts remain identical to native d7bd91ac. Component
checks are not full native gameplay verification.
