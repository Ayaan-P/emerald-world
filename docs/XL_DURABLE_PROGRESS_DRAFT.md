# Opt-in offline XL story persistence

On POSIX native builds, `--generated-map path --generated-progress on` opts into a private `<trainer-save>.generated-story` sidecar. The existing 64-entry offline XL story cache is keyed by trainer ID and a SHA-256 identity over the world, cast and graph data. The game journals state transitions in two checksummed snapshots using the native save boundary's no-symlink, owner, hard-link and lifetime-lock checks. It never modifies the trainer save for this feature. Invalid, unsafe, unavailable or locked sidecars fall back to session-only progress without replacing the file. Windows currently falls back to session-only; this draft does not implement Windows persistence.

Tests use disposable files and verify process restart, trainer separation, checksum recovery, bad permissions and symlink refusal. The native CI attempts a game process restart using a disposable trainer save and checks that a three-state XL story resumes while the original save remains unchanged. Until CI passes, actual restart behavior is unverified. This is offline-only; multiplayer progression and integration are separate. The sidecar is created only when the flag is explicitly supplied and is under 10 KB.

This draft uses sidecar format XLP2. An earlier experimental XLP1 sidecar is not migrated or overwritten; the game falls back to session-only progress if it encounters one.
