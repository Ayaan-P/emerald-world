# Generate a shared cave from the host launcher (draft)

The local desktop host's Optional GM page now includes a cave description and **Generate shared cave** action. The owner must already be hosting a compatible local world. Before any model request, the launcher asks for confirmation and explains that the description is sent to the configured provider and may incur charges. It authors a 63×63 cave with a biome and bounded custom wildlife, then installs the validated map into that same owner's running authority. Compatible experimental CAVE5 clients can fetch it without restarting. This does not expose the owner's controls to ordinary trainers or hosted-service guests.

Generation runs on the launcher's existing serialized background executor so the native game can continue. The current generated cave cannot be replaced while any connected trainer is inside. Occupancy is checked both before a model call and by the authority again when installing, so a player entering during generation blocks the replacement. The result stays for the host session unless the authority was started with generated-cave persistence. Trainer saves are not modified by generation. If the host or selected world changes before installation, the result is discarded. Errors shown to the UI do not expose provider output or credentials.

This is a local desktop-host flow, not the React player launcher or hosted service. Tests use a mocked provider, an in-memory production authority and a fake GUI confirmation/executor; no real model request, real desktop interaction or real two-client game session was performed. Experimental native client gates and the cave integration limitations from the parent drafts still apply.
