# Experimental large generated cave

This opt-in, offline-only draft grows an authored cave from 31×31 to 63×63 cells, more than four times the area. The `EWGMAP04` format contains 3,969 inert floor/wall bytes. Both the author-side encoder and native loader independently enforce closed borders, walkable spawn and exit, and connectivity of every floor. Large cave staging cannot occur while online, while already inside, or during entry. An invalid replacement does not disturb the prior staged map. The native backup map remains within its existing capacity with the view border included.

Use an explicit model call to create a new file: `python3 -m world.author_cave 'a sprawling crystal cave' --large-offline-output cave.bin`. The theme is sent to the configured provider and may incur usage charges. No model-authored code is executed; the author returns bounded rooms and links. With a native build using `GENERATED_MAP_READY=1 GENERATED_MAP_LARGE=1`, launch offline with `--generated-map cave.bin`. The other cave gates remain independent; autotiling makes the layout easier to read. File creation is exclusive and will not overwrite a file.

This first slice has cave geometry and standard cave encounters, not custom wildlife or multi-client sharing for large maps. The 31×31 shared protocol remains unchanged and never receives a large template. The existing cave return/unsaved-instance boundaries still apply. The exit is at 61,61, with the existing World menu return also available. This is not a fully unlimited map engine or a new region. Component tests exercise real native validation, collision and runtime layout; see exact-head CI for the actual native walk and save-isolation result. No live model call was made.
