# Agent-authored interaction graphs (experimental)

This is a reusable, declarative interface for an agent to create interactive generated outdoor areas. The input JSON supplies a room-and-link terrain blueprint, one to three characters, an initial state, and up to 24 interaction rules. Each rule specifies the current state (0–15), a character local ID (1–3), a next state (0–15), and bounded literal dialogue. An NPC interaction uses the rule for the player's current state; if no rule matches, the NPC's ordinary dialogue plays and the state is unchanged. Duplicate state/character rules are rejected. For example, the bundled JSON describes a three-step conversation, but the engine executes the same interpreter for any valid graph.

`python -m world.wilds_events examples/agent_event_area.json area.bin` validates and compiles a JSON document to a new file without overwriting an existing file. This compiler does not call an LLM, execute model-authored code, send data to a provider or publish a map. An agent can generate and submit the data using its existing execution environment. Dialogue is restricted to one or two short ASCII lines; the native client independently validates all metadata, event rules, characters, geometry and padding before staging. Fixed native code performs transitions. The graph is reset to its initial state on entering the generated area; it is per client and not persistent player progression.

To test the offline native client, build with `GENERATED_MAP_READY=1 GENERATED_MAP_AUTOTILE=1 GENERATED_MAP_LARGE=1 GENERATED_MAP_WILDS=1 GENERATED_WILDS_GUIDE=1 GENERATED_WILDS_CAST=1 GENERATED_WILDS_EVENTS=1`, then pass `--generated-map area.bin`. The shared extension allows an authorized owner agent to publish the same JSON directly with `python -m world.wilds_events examples/agent_event_area.json --admin-socket /path/to/owner.sock`. The authority validates all bytes, binds the graph to the map identity and distributes it to compatible CAVE9 clients. Older clients receive CAVE NONE. The owner API refuses replacing an area while trainers are inside; same-identity reconnect preserves each client’s current state. The graph is shared but each trainer’s state remains independent and resets on entry. No live in-place edits, shared state, persistent progress, item/reward actions, battles, arbitrary scripts, real model call or live two-client session is claimed. Review the exact-head CI for the native playthrough result.
